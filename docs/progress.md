- Organized the HTTP layer: `src/api/routes/` is now versioned

- Added `src/core/security.py` for auth (see section below).

### Key decisions / gotchas

- **Neon URL normalization** — Neon gives a `postgresql://...?sslmode=require&channel_binding=require`
  string. SQLAlchemy's asyncpg driver crashes on it with
  `TypeError: connect() got an unexpected keyword argument 'sslmode'`. `Settings.database_url`
  rewrites the scheme to `postgresql+asyncpg://` and strips the libpq-only params
  (`sslmode`, `channel_binding`, `sslnegotiation`); SSL is passed through
  `database_connect_args` instead.
- **Neon pooler** — the pooled endpoint uses PgBouncer, so prepared-statement caching
  is disabled (`statement_cache_size=0`) to avoid protocol errors.
- **Engine** — `pool_pre_ping=True`, `pool_recycle=300`, `pool_size=5`,
  `max_overflow=10`; disposed on app shutdown via the FastAPI `lifespan`.
- **Migrations** — `Base` uses a constraint naming convention so autogenerated
  names are stable; Alembic uses the same URL/connect args as the app.
- **Linting** — `src/alembic/versions` is excluded from ruff (generated code).

## 2026-10-12 — Auth: signup, login (JWT), `/auth/me`, logout

### Summary

Implemented email/password auth with JWT using PyJWT and Argon2 password hashing
(`pwdlib`). Backend-only, written test-first (TDD) with an in-memory SQLite suite.

### Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/signup` | no | Create user; optional `organization_name` creates an org and sets `role=owner` |
| POST | `/auth/login` | no | Verify credentials, return `{access_token, token_type}` |
| GET | `/auth/me` | bearer | Return the authenticated user |
| POST | `/auth/logout` | bearer | Stateless logout — returns 204, client discards token |

### Decisions

- **Org relationship** — `User.org_id` is now nullable; a `role` column
  (`owner`/`member`, null when no org) records ownership. Created at signup only
  for now; invites are planned later.
- **Hashing** — `pwdlib` + Argon2 (`PasswordHash.recommended()`).
- **Tokens** — PyJWT, HS256, `sub` = user UUID, `exp` = 30 min (configurable),
  no refresh token yet.
- **Logout** — stateless (no blocklist); token invalidation on the server is a
  future enhancement if needed.
- **Security defaults** — bcrypt-style best practices: `min_length=8` password,
  `EmailStr` validation, `Authorization: Bearer` via `HTTPBearer`.

### Config (`.env`)

- `JWT_SECRET` (random, generated), `JWT_ALGORITHM=HS256`,
  `ACCESS_TOKEN_EXPIRE_MINUTES=30`. Exposed via `src/config.py`.

### Migration

- `6e6558c226d8` — make `users.org_id` nullable, add `users.role`.
  Applied to Neon; `alembic check` clean.

### Verified

- `pytest`: 19 tests pass (security unit tests + auth route/integration tests on
  async SQLite with `get_db` overridden).
- Live smoke test against Neon: signup (201, owner, org created) → login (200,
  token) → `/auth/me` (200) → `/auth/logout` (204); bad token → 401. Smoke data
  cleaned up afterwards.
- `ruff check` + `ruff format --check` pass on `src` and `tests`.

## 2026-10-13 — Modular refactor: `src/app/`, feature modules, `migrations/` at root

### Summary

Restructured the API into the requested src-layout: the app package moved to
`src/app/` (`app.*` imports), routes were split into feature modules under
`src/app/modules/`, Alembic scripts moved to `migrations/` at the project root,
and tests were reorganized under `tests/modules/` and `tests/core/`. Behavior is
unchanged; endpoint paths moved under `/api/v1`.

### Changes made

- Moved everything under `src/` into a `src/app/` package (git mv, history kept).
  `src/__init__.py` removed; `src/` is now the source root and `app` the package.
- Feature modules: `auth/` (router/schemas/service), `users/` (model/router/schemas/service),
  `organizations/` (model/router/schemas/service). The old flat `src/models/`,
  `src/schemas/`, `src/api/routes/` trees were deleted.
- Business logic extracted into a service layer: `auth/service.py` orchestrates
  `users/service.py` + `organizations/service.py`; routers are thin.
- `core/exceptions.py` adds `AppError` (message + status_code), surfaced as JSON
  by a global exception handler in `create_app()` — services raise it instead of
  leaking `HTTPException` into business code. All prior 401/403/409 behaviors preserved.
- `core/logging.py` adds `configure_logging()`, called from `create_app()`.
- `api/deps.py` now owns `get_db`, `get_current_user`, `CurrentUser`, and a
  `require_role(*roles)` dependency factory. `db/session.py` keeps engine/session
  only.
- `db/registry.py` imports both model modules so Alembic autogenerate sees every
  table; `migrations/env.py` imports it (plus `app.core.config`, `app.db.base`).
- `alembic.ini`: `script_location = %(here)s/migrations`, `prepend_sys_path = src`.
- `pyproject.toml`: fastapi entrypoint `app.main:app`, `pythonpath = ["src"]` for
  pytest, ruff excludes `migrations/versions`.
- Routes are now served under `/api/v1` (e.g. `POST /api/v1/auth/signup`).
- Added `.env.example`-adjacent app-level `.gitignore`; README rewritten with
  setup/run/migrate/test commands.

### Gotchas

- **uvicorn/fastapi import path** — with `src/app`, `import app` only resolves
  when `src` is on `sys.path`. `fastapi dev <path>` handles this automatically
  (pass `src/app/main.py`); uvicorn needs `--app-dir src`. The `[tool.fastapi]
  app-dir` key is not supported by fastapi CLI, so plain `fastapi dev` was dropped
  from the README.
- **Ruff on the registry** — a bare `import app.modules.x.models  # noqa` triggers
  RUF100/F401 quirks; using `from ... import models as _` + `__all__` keeps it
  self-documenting and lint-clean.
- **Pytest** — `pythonpath = ["src"]` keeps `app.*` imports working from any test
  directory.
