### Key decisions / gotchas

- **Neon URL normalization** — Neon gives a `postgresql://...?sslmode=require&channel_binding=require`
  string. SQLAlchemy's asyncpg driver crashes on it with
  `TypeError: connect() got an unexpected keyword argument 'sslmode'`. `Settings.database_url`
  rewrites the scheme to `postgresql+asyncpg://` and strips the libpq-only params
  (`sslmode`, `channel_binding`, `sslnegotiation`); SSL is passed through
  `database_connect_args` instead.
- **Neon pooler** — the pooled endpoint uses PgBouncer, so prepared-statement caching
  is disabled (`statement_cache_size=0`) to avoid protocol errors.
- **Engine** — `pool_pre_ping=True`, `pool_recycle=300`, `pool_size=5`,
  `max_overflow=10`; disposed on app shutdown via the FastAPI `lifespan`.
- **Migrations** — `Base` uses a constraint naming convention so autogenerated
  names are stable; Alembic uses the same URL/connect args as the app.
- **Linting** — `src/alembic/versions` is excluded from ruff (generated code).

## 2026-10-12 — Auth: signup, login (JWT), `/auth/me`, logout

### Summary

Implemented email/password auth with JWT using PyJWT and Argon2 password hashing
(`pwdlib`). Backend-only, written test-first (TDD) with an in-memory SQLite suite.

### Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/signup` | no | Create user; optional `organization_name` creates an org and sets `role=owner` |
| POST | `/auth/login` | no | Verify credentials, return `{access_token, token_type}` |
| GET | `/auth/me` | bearer | Return the authenticated user |
| POST | `/auth/logout` | bearer | Stateless logout — returns 204, client discards token |

### Decisions

- **Org relationship** — `User.org_id` is now nullable; a `role` column
  (`owner`/`member`, null when no org) records ownership. Created at signup only
  for now; invites are planned later.
- **Hashing** — `pwdlib` + Argon2 (`PasswordHash.recommended()`).
- **Tokens** — PyJWT, HS256, `sub` = user UUID, `exp` = 30 min (configurable),
  no refresh token yet.
- **Logout** — stateless (no blocklist); token invalidation on the server is a
  future enhancement if needed.
- **Security defaults** — bcrypt-style best practices: `min_length=8` password,
  `EmailStr` validation, `Authorization: Bearer` via `HTTPBearer`.

### Config (`.env`)

- `JWT_SECRET` (random, generated), `JWT_ALGORITHM=HS256`,
  `ACCESS_TOKEN_EXPIRE_MINUTES=30`. Exposed via `src/config.py`.

### Migration

- `6e6558c226d8` — make `users.org_id` nullable, add `users.role`.
  Applied to Neon; `alembic check` clean.

### Verified

- `pytest`: 19 tests pass (security unit tests + auth route/integration tests on
  async SQLite with `get_db` overridden).
- Live smoke test against Neon: signup (201, owner, org created) → login (200,
  token) → `/auth/me` (200) → `/auth/logout` (204); bad token → 401. Smoke data
  cleaned up afterwards.
- `ruff check` + `ruff format --check` pass on `src` and `tests`.

## 2026-10-19 — Web: auth screens (signup, login, account)

### Summary

Built the first real frontend for Ragnest in `apps/web/` — Next.js 16 App Router,
React 19, Tailwind v4. Three screens: sign up, sign in, and a protected account
page that proves the token works. Designed as permanent product surfaces, not a
throwaway API harness.

The three backend endpoints exercised: `POST /api/v1/auth/signup`,
`POST /api/v1/auth/login`, `GET /api/v1/users/me`.

### Structure (`apps/web/`)

```
apps/web/
├── app/
│   ├── layout.tsx              # Archivo + Newsreader via next/font
│   ├── globals.css             # design tokens + the highlight sweep
│   ├── page.tsx                # protected account page
│   ├── login/page.tsx
│   ├── signup/page.tsx
│   ├── (protected)/layout.tsx  # session-cookie guard
│   └── api/auth/
│       ├── signup/route.ts     # proxy -> API, sets cookie
│       ├── login/route.ts
│       ├── logout/route.ts     # clears cookie
│       └── me/route.ts
├── components/
│   ├── auth-shell.tsx          # frame + retrieved-sentence motif
│   ├── auth-form.tsx           # shared signup/login form (client)
│   ├── field.tsx               # underlined input + inline error
│   ├── button.tsx
│   └── sign-out.tsx
└── lib/
    ├── api.ts                  # fetch wrapper + FastAPI error mapping
    ├── session.ts              # httpOnly cookie read/write
    ├── dates.ts                # parse zone-less API timestamps as UTC
    └── token.ts                # read exp from the JWT for display
```

### Key decisions

- **Proxy instead of CORS.** The API has no `CORSMiddleware`, so the browser
  cannot call `:8000` from `:3000`. Next route handlers call the API server-side
  and store the token in an **httpOnly, SameSite=Lax cookie** (`ragnest_session`,
  `maxAge` 1800 to match the token). No API changes; the token never reaches
  client JS. The API URL lives in `API_URL` (`.env.example`), server-only.
- **Design direction — ink and paper.** The product's world is a passage lifted
  out of a document, so the motif is a highlighter mark behind a retrieved
  sentence, cited to `file, page`. Palette: paper `#f8f6f1`, ink `#171a2b`,
  muted `#5b5f73`, action `#2b3a8f`, saffron `#f5c445`, rule `#ddd9ce`,
  control `#8f8a78`, danger `#a3341f`. Type: **Newsreader** (serif) for headings
  and quoted content, **Archivo** (sans) for the interface. Light-only for now;
  the scaffold's `prefers-color-scheme` block was removed because it fought the
  palette.
- **Error copy is the API's, translated.** 409 → "That email already has an
  account. Sign in instead."; 401 login → "Email or password isn't right.";
  422 → per-field messages from Pydantic's `detail` array; unreachable API →
  "Can't reach the API. Is it running on port 8000?".
- **No refresh token.** The session ends after 30 minutes. The account page
  shows "Signed in until <time>", and a 401 from `/users/me` redirects to
  `/login`.

### Gotchas

- **Repo `.gitignore` swallowed `apps/web/lib/`.** The Python template's `lib/`
  rule is unanchored, so it matched any directory named `lib` at any depth. Now
  anchored to `/lib/`.
- **API timestamps have no timezone.** `created_at` is stored UTC but serialized
  as `2026-10-19T10:07:15.377167` with no `Z`. `new Date(...)` reads that as
  local time and shifted "Member since" by the viewer's offset (5h30m here).
  `lib/dates.ts` appends `Z` when no zone is present. **The API should emit
  timezone-aware datetimes** — worth fixing server-side later.
- **Tailwind `outline-none` kills the focus ring.** It sets
  `--tw-outline-style: none`, which the shared `:focus-visible` ring inherits, so
  focused inputs showed no outline. Dropping the utility restores it.
- **`router.replace()` + `router.refresh()` fight each other.** Both trigger a
  server round trip and the navigation stalled for seconds.
- **Prefetched payloads outlive the session change.** `next dev` disables
  prefetching, so signing in looked fine there; under `next start` the client
  router replayed a `/` payload that had been prefetched while signed out (it
  still carried `NEXT_REDIRECT;replace;/login`), bouncing the user back to the
  form. Auth changes now use a full `window.location.assign()`, with the lint
  rule suppressed and the reason inline. **Verify auth flows against
  `next start`, not only `next dev`.**
- **Argon2 makes signup slow.** `POST /auth/signup` takes 3.5–4.8s against the
  local API even with a warm server, so the UI sits in "Working…" for several
  seconds. That is backend hashing cost, not a frontend stall; worth tuning the
  Argon2 parameters (or moving hashing to a threadpool) before release.
- **Cache Components is on** (`next.config.ts`). Pages that read cookies or call
  the API cannot be prerendered; they set `export const instant = false` to opt
  out of the dev-time validation warning rather than being wrapped in Suspense
  they do not need.
- **`next dev` rewrites `apps/web/AGENTS.md`.** It appends Next's own
  agent-rules blocks on every run. The file is still the API's copy — it needs
  rewriting for the web app.

### Verified

- `pnpm build` succeeds; `/` and the four `/api/auth/*` handlers are dynamic,
  `/_not-found` static. `tsc --noEmit` and `eslint` clean.
- Server contract against the live API: signup 201 → me 200 → logout 204 → me

- Driven in headless Chrome: field-level validation renders, signup lands on `/`

## 2026-11-06 — API: Milestone 6 chat (RAG)

### Summary

Workspace chat is live in the API: a member creates a conversation, asks a
question, and receives a grounded, citation-bearing answer streamed as SSE.
Retrieval, embeddings and pgvector are reused from Milestone 5; generation goes
to Groq's OpenAI-compatible endpoint over `httpx` (no SDK, no new dependency).
The web chat UI and document UI remain a separate milestone.

### What shipped

- `app/modules/chat/` follows the existing module shape: `constants.py`,
  `llm.py` (provider protocol + Groq client), `deps.py`, `models.py`,
  `types.py`, `prompts.py`, `schemas.py`, `service.py`, `router.py`.
- Routes under `/api/v1/workspaces/{workspace_id}/conversations`:
  `POST` create, `GET` list the author's conversations newest-first,
  `GET /{id}` detail with messages, `DELETE /{id}`, and
  `POST /{id}/messages` streaming SSE.
- SSE contract: `sources` → `token`* → `done`. `error` is terminal and never
  followed by `done`. `done.cited` holds the valid, de-duplicated `[n]` markers
  found in the answer.
- Conversations are private to their author: another member gets 404, a
  non-member gets 403 at the workspace gate. Both the API check and the SQL
  filter include `created_by`.
- Grounded prompt: numbered source blocks, 12k-character context, last 6
  history messages capped at 6k characters. The model must cite with `[n]` or
  reply with the fixed refusal.
- Zero retrieved chunks skip the model entirely and persist both the question
  and the refusal with `finish_reason="no_context"`.
- Failure modes: pre-token provider 429 → JSON 429, other/empty completion →
  JSON 503 (the question row survives); post-token failure → terminal
  `event: error` plus a partial assistant row with `finish_reason="error"`;
  embedding failure → 503 with nothing persisted. Disconnect persists partial
  text as `finish_reason="cancelled"`.
- Migration `7c1e4a9b2d3f` adds `conversations` and `messages`, cascading from
  workspaces/conversations. Citations are a `JSONB` snapshot (JSON on SQLite)
  so they survive document deletion.
- Config gained `LLM_API_KEY` (required), `LLM_BASE_URL`, `LLM_MODEL` and
  `LLM_REASONING_EFFORT`; generation uses `openai/gpt-oss-120b` with
  `reasoning_effort="low"` and never exposes reasoning deltas.

### Discovered during the Neon smoke test

- **Naive vs aware datetimes.** `TimestampMixin` columns are `TIMESTAMP WITHOUT
  TIME ZONE`; asyncpg rejects an aware `datetime` bound to them. Conversations
  now use `_utcnow_naive()` while `messages.created_at` (timestamptz) keeps
  aware UTC. SQLite accepted both, so only the live run caught it.
- **Blank `.env` values beat defaults.** A `LLM_BASE_URL=` line arrived as an
  empty string and made the provider POST to a relative URL. A settings
  validator now restores the base URL/model defaults and strips
  `LLM_REASONING_EFFORT`.
- **Groq emitted full-width citation brackets (`【1】`).** `parse_cited` now
  accepts ASCII, full-width square, and CJK corner brackets while keeping only
  markers in `1..len(sources)`.

## 2026-11-06 — Retrieval: repair stuck documents, fix backfill CLI

### Problem

Several workspaces held documents stuck at `embedding_status = "pending"` with
zero chunks, so every chat question took the `no_context` path and returned the
fixed refusal. The documents had been uploaded while the dev server was
restarted before the in-process `BackgroundTasks` indexing job ran; the upload
row survived, the task did not.

The documented repair path was also broken: `python -m
app.modules.retrieval.backfill` failed immediately with
`NoReferencedTableError: documents.uploaded_by -> users.id`, because the CLI
module imported only `Document` and `DocumentChunk`. SQLAlchemy's mapper
configuration needs every model registered. Tests missed it because the test
harness imports `app.db.models` first.

### Fix and repair

- `backfill.py` now imports `app.db.models` at module level, so the CLI
  registers the full metadata before configuring mappers.
- Added a subprocess regression test that imports the CLI in a fresh
  interpreter and calls `configure_mappers()`; it fails without the import.
- Ran the backfill against Neon: **33 documents ready, 0 failed** across
  `Business`, `startup`, both `Sidebar QA` workspaces, both `Single Doc`
  workspaces, and `Chat demo`. The two `Empty Workspace` entries have no
  documents.
- Verified real retrieval on existing documents (cosine scores 0.80–0.86) and
  a full live upload → indexing → SSE chat run: `sources` populated, grounded
  answer with `[1]`, `finish_reason: "stop"`.

### Note

`BackgroundTasks` are in-process: a reload or restart between the upload
response and the task loses the job. The backfill remains the repair path; a
startup sweep for non-`ready` documents would be a separate design decision.

## 2026-11-07 — API: opt-in CORS allowlist

### Summary

The API had no CORS configuration at all. Added an explicit, environment-driven
allowlist so cross-origin browser calls can only come from the deployed web
origin.

### Decisions

- `CORS_ORIGINS` is a comma-separated string, empty by default. The
  `cors_origins` property trims entries and strips trailing slashes.
- `create_app()` adds `CORSMiddleware` only when the allowlist is non-empty.
- Allowed methods: `GET`, `POST`, `DELETE`, `OPTIONS`; allowed headers:
  `Authorization`, `Content-Type`; credentials disabled (the API uses bearer
  tokens, not cross-origin cookies).
- This is a browser boundary, not API access control. The web app fetches the
  API server-side, so CORS never applies to that path, and `curl` ignores it.
  JWT + workspace membership remain the authority.
- Production sets `CORS_ORIGINS=https://ragnest.vercel.app` on Render.

### Verification

- New preflight tests: the configured origin gets `200` with matching
  `access-control-allow-origin`; another origin gets `400` and no allow header;
  an empty allowlist adds no CORS headers.
- Config tests cover comma splitting, trimming, trailing-slash normalization,
  and the empty default.
- `uv run pytest` — 199 passed; `uv run ruff check app tests` and
  `uv run ruff format --check app tests` — clean.
