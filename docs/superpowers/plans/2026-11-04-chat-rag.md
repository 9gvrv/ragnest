# Chat (RAG) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ask a question in a workspace, stream a grounded answer, and persist citations to the source chunks.

**Architecture:** A new `app/modules/chat/` follows the retrieval module: provider protocol, thin router, service, SQLAlchemy models. Generation goes to Groq's OpenAI-compatible API over `httpx`; embeddings and search are reused from retrieval. Messages stream as SSE.

**Tech Stack:** FastAPI, async SQLAlchemy (Postgres/Neon in prod, SQLite in tests), httpx, Pydantic, Alembic, pytest.

**Spec:** `docs/superpowers/specs/2026-11-04-chat-rag-design.md`

## Global Constraints

- No new runtime dependencies. Generation is `httpx` + Chat Completions.
- Tests never touch Neon, Gemini, or Groq; they use in-memory SQLite and fakes.
- `LLM_API_KEY` is required; `LLM_BASE_URL=https://api.groq.com/openai/v1`,
  `LLM_MODEL=openai/gpt-oss-120b`, `LLM_REASONING_EFFORT=low` are defaults.
- Migration `down_revision = "299585b2a1a6"`.
- Every API route stays under `/api/v1`; the module is registered in
  `app/api/router.py`.
- `ruff` line length 100; run `uv run ruff check app tests` and
  `uv run ruff format --check app tests`.
- Never log or commit either key. Never persist chain-of-thought deltas.
- Citation markers are only valid from `[1]` to `len(sources)`.

## Review Focus

- Zero retrieved chunks: fixed refusal, no LLM call, `no_context` row.
- Groq 429/5xx before the first token: JSON error, user row still exists.
- Groq failure after tokens: terminal `event: error`, partial row, no `done`.
- Non-author member: 404; non-member: 403 at the workspace gate.
- Markers `[99]`, duplicates, and `[1][2]` in the answer.
- Empty completion: an error, never a blank assistant row.
